# 全回归测试清单（E2E 用户行为主线版）

> 版本：2026-07-29 v2
> **总规则：每条测试的最终落脚点必须是模拟真实用户行为的端到端测试，以产品可流畅演示为最终目的。**
>
> 三层结构：
> - **验收层（本文件主体）**：用户主线场景 S1-S11，操作走真实产品界面/接口，断言落在"用户可见结果 + 数据库真实状态"——这就是演示脚本
> - **守卫层**：下层单元/契约测试（run_all 各层），只用于快速定位，不算验收
> - **门禁**：每次发版前 S1-S11 全绿 + 层 13 性能手动门禁通过
>
> 动线说明：对话能力不在 Web 控制台——控制台（agent-chat-ui，:3000）只有管理界面（控制台/表设计/数据源/权限/设置，根路径重定向到表设计器）；所有对话指令一律在 MCP 客户端（Reasonix / Kimi Code / Claude Code 等，已接入 data-engine/mcp_server.py）中发送。高危操作（建库/结构变更等）在 MCP 通道挂起，由管理员到控制台「权限」页顶部"待审批"区点"批准执行"后才会真正执行。

---

## 验收层：用户主线场景（演示脚本 = 测试脚本）

每个场景三栏：**用户操作**（模拟真人）→ **可见断言**（界面上看到什么）→ **底层断言**（DB/文件真实状态）。

### S1 启动与首屏（1 分钟）
- 操作：启动器启动 → 浏览器自动打开控制台（:3000，根路径重定向到表设计器）→ 看首屏
- 可见：管理服务（:2025）与控制台（:3000）两服务就绪、表设计器画布正常加载（表卡片及连线）、无报错弹窗
- 底层：2025/3000 端口可达；数据库自动备份文件生成
- 守卫：启动器 re-exec 不误杀（端口判活）、冷启动 <60s（层13）

### S2 建行业与交互式建表（3 分钟）
- 操作：在 MCP 客户端发送"我想创建一个建筑工程行业的数据库"→ AI 提案表结构 → 用户回复"材料表加个规格字段" → AI 改 → 确认后 AI 发起建表（高危，挂起）→ 控制台 → 权限页"待审批"区点"批准执行"
- 可见：提案/修改循环不限轮次；执行前有完整表结构提案；权限页待审批区出现对应条目（工具名+影响说明+剩余时限）；批准后提示成功
- 底层：行业 YAML 落盘（schemas 4 表）；物理表结构与 YAML 一致（层8口径）
- 异常分支：与既有表撞名 → 如实报冲突，不静默共库（已知冻结项观察）
- 守卫：行业注册包解析/校验（层2）、行业 lint（层15）

### S3 上传文件入库——文本 PDF（5 分钟）
- 操作：把定额文件放入工作区（如 data-engine/uploads/）→ 在 MCP 客户端发送"把 uploads/ 下 <文件名> 这份文件里的定额项目和材料价格录进库"（AI 经 upload_file/process_file 入库）→ 看进度 → 看报告
- 可见：进度心跳逐批可见；报告含 批次数/+N条/冲突/未映射及确认引导，零新增显示 +0 不冒充
- 底层：quota_items 有真名真价；quota_materials 按码关联（FK=主表数字 id）；向量库有该文件 prose；重复执行报冲突不重复插
- 守卫：层5（Excel/Word）、test_18 管线固化（转置/歧义/去重/链接列/归一）

### S4 扫描件与图片入库（5 分钟）
- 操作：把扫描 PDF（无文本层）放入 uploads/ → 在 MCP 客户端发同一入库指令 → 再放一张单页图片 → 同一指令
- 可见：用户零感知 OCR 过程；报告同样式；图片重灌报幂等
- 底层：扫描页全部 OCR 成功（日志可审计）；新编码入库；图片与已入库区间重叠处 0 新增
- 异常分支：OCR 未配置 token → 如实告知降级，不静默跳过

### S5 数据核验（2 分钟）
- 操作：切到表设计器 → 展开主表卡片 → 看连线 → 点"整理布局" → 切控制台看记录数
- 可见：4 表 3 关系、被引用表在左箭头右指、库框自适应、字段列表可展开
- 底层：mgmt 返回的 schema 与物理表一致；卡片数据非缓存旧值
- 守卫：层8 Schema 一致性

### S6 查询五连问（5 分钟，在 MCP 客户端依次发送）
1. "现在数据库里有哪些表？" → 表清单+字段+外键
2. "quota_items 有多少条记录？" → 精确数字
3. "统计各材料单价的平均值，按材料分组" → 聚合正确
4. "查询每条主表记录对应的明细数据" → JOIN 结果主细齐全
5. "上传的定额文档里，砌筑工程的工作内容讲了什么？" → 向量命中原文页码
- 可见：答案含数据内容（表格渲染以所用 MCP 客户端为准）、trace id 可追踪、无"操作失败"误报（待实测）
- 底层：与直接 SQL 对账一致；含 503 价格/含"连接件"材料的结果不被误判为故障（Q3 事故）
- 异常分支：问不存在表/字段 → 诚实报错+可用提示；无 FK 的表求关联 → 如实拒绝

### S7 记录级增删改查（MCP 客户端直接指令，5 分钟）
- 增："往 quota_items 插入一条 A1-999 测试墙，基价 100" → "再批量插 3 条：…" 
- 改："把 A1-999 的基价改成 200" → "把基价小于 50 的全部标记…（批量改）"
- 删："删除 A1-999" → "删除刚才批量插的 3 条（批量删）"
- 查：确认每一步结果
- 可见：每步有明确成功/冲突/拦截提示；改 id 被阻止；无条件批量删被拒绝
- 底层：与提示一致的DB状态；唯一键/CHECK/类型校验逐条生效；全角数字可入
- 守卫：CHECKLIST 记录级用例 + test_19（记录 DML 补齐 5.2/5.6/5.8/5.9）

### S8 表结构编辑（设计器 + MCP 客户端双通道，3 分钟）
- 操作：在 MCP 客户端发送"给 quota_items 加一个 备注 TEXT 字段" → 设计器确认可见 → "把 备注 改名为 注释"（或不支持则验证诚实拒绝）→ "给 quota_code 建唯一索引" → "删除 注释 字段"
- 可见：设计器刷新即见；被引用字段删除被阻止并说明
- 底层：YAML↔DB 始终一致；唯一索引物理生效（重复值插入被拒）
- 守卫：层8 + CHECKLIST 字段级用例

### S9 权限演示（3 分钟）
- 操作：控制台 → 权限页"数据源规则"页签把 A 库的写操作全部禁止（保存并生效）→ 在 MCP 客户端尝试往 A 库写 → 拒绝；从 A 库读数据 → 写入 B 库 → 成功
- 可见：拦截提示明确到 库×操作；迁移场景全程顺
- 底层：库级权限独立生效；表/列级（如已实现）同口径
- 守卫：层17 + 表/列级权限固化用例

### S10 异常与恢复（3 分钟）
- 坏文件：把损坏 PDF 放入 uploads/ 后在 MCP 客户端发入库指令 → 如实报错不崩不静默
- 大文件：400+ 页 PDF 同口径发指令 → 流式处理内存不爆、进度可见、可续批
- 提取失败：模拟 AI 服务异常 → 报告明示"第 X 批未入库"，重发指令可续
- 服务重启：入库中途重启启动器 → 已入库数据保留，重灌幂等

### S11 清理与重演（2 分钟）
- 操作：清空演示行业数据 → 按 S2-S6 原样重跑一遍
- 可见：全程无残留干扰（旧行业/旧表/旧向量不串戏）
- 底层：行业隔离干净；重演结果与首轮一致（可重复演示 = 可重复测试）
