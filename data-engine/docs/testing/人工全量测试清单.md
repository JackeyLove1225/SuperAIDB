# 人工全量测试清单（复制粘贴版）

> 用法：按组顺序测。对话类直接把**指令列**的文字复制到 MCP 客户端（Reasonix / Kimi Code / Claude Code 等，已接入 data-engine/mcp_server.py）发送，对照**预期**判定通过与否。
> 界面类在 Web 控制台（:3000）按**操作**列点击，对照**预期**判定。控制台只有管理界面（控制台/表设计/数据源/权限/设置），没有聊天页。
> 建议每组在 MCP 客户端开**新会话**，避免上下文互相影响。
> 高危操作（建库/结构变更等）会在 MCP 通道挂起：到控制台「权限」页顶部"待审批"区点"批准执行"后才会真正执行。
> 测试记录统一用 `MAN-` 前缀，收尾一次性清理。
> 标记：⭐ = 核心卖点（演示必过），⚠️ = 选测（依赖额外材料或环境）

## 翻车速查

| 现象              | 先看哪里                                            |
| --------------- | ----------------------------------------------- |
| 答非所问（该列表的答成了清单） | 换更明确的说法重发；必现则看 data-engine/logs/ 最新日志的"路由决策"    |
| 改/删提示"请先查询"     | 正常机制——先说一句查询建立选择集，再说改/删                         |
| 插入报冲突           | 唯一键重复——正常拦截，不是 bug                              |
| 权限拦截不生效         | 权限页是否点了"保存并生效"；规则测试部件干跑一条验证                     |
| 高危操作一直挂起没人管     | 控制台 → 权限页顶部"待审批"区，点"批准执行"或"拒绝"                  |
| 入库报告"操作失败"      | data-engine/logs/ 与 backend.log 最后 50 行；AI key（DeepSeek）是否有效 |
| OCR 不可用         | OCR_API_TOKEN / 令牌是否配置                          |
| 页面假死/白屏         | 重启应用；仍现则看浏览器控制台红字                               |
